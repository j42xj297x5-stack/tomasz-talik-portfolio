# Snapshot Workflow

## Purpose
Snapshots capture meaningful project checkpoints, not every small commit.

## Location
`docs/current/audits/snapshots/`

## Required filename convention
`YYYY-MM-DD_HH-MM-SS__snapshot__<short-topic>.md`

Example:
- `2026-05-22_16-20-00__snapshot__pre-three-mvp.md`

## Snapshot content template
- Current project status
- Important changed files
- Known decisions
- Known risks
- Next planned steps
- References to relevant audits

## Relationship to audits
Snapshots should reference key audits and help define the baseline for future incremental reviews.
