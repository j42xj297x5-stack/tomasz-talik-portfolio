## Implemented language flow

1. `src/main.js` owns `state.language`; `renderLanguageSelection` offers `pl` and `en` before mode selection. `setLanguage` assigns it, sets `document.documentElement.lang`, refreshes the shared audio control and persists the selection.
2. Persistence uses localStorage key `portfolioEntrySelection`; `loadStoredSelection` accepts only `pl`/`en`. On restored state, the entry module sets `document.documentElement.lang` before rendering modes.
3. Classic 2D receives `language: state.language || 'en'` directly in `startClassic2D`; it resolves `CLASSIC_COPY`, `INTERFACE_COPY`, and `resolvePortfolioNodes(language)`.
4. Experience 3D is dynamically imported after the root `lang` is set. It reads `document.documentElement.lang`, calls `resolvePortfolioNodes`, and passes the language to its intro and overlay owners.
5. Experience VR is dynamically imported after the root `lang` is set. At module evaluation it normalizes exactly `lang === 'pl' ? 'pl' : 'en'`, resolves its bootstrap `COPY` and portfolio nodes, and passes `locale: language` to Guidance/player-panel/projection owners. The controller SVG path is selected with the same language.
6. Bypasses remain: the canonical Monkey catalog is PL-only; current objectives explicitly return `null` outside PL; Player Guide tool/knowledge sections exist only under `pl`; Furnace and final credits draw hardcoded Polish/mixed canvas text without locale resolution.

- Ordered authority set requested by the task, then the seven starting runtime files.
- Actual imports/consumers for shared overlays, portfolio nodes, portal cards and all player-facing Experience VR Guidance, Monkey, objective, Player Guide, Furnace, Astrolabium, Asterion/Resonator, Rune/progression, credits and debug gate paths.
- Accessibility sinks (`aria-label`, `title`, meaningful `alt`), canvas text, dynamic counters/objectives, and strings assembled from fragments.

### Repository-wide completeness searches

- First pass: Polish-diacritic search over `src`, `public` and `index.html` for runtime text file types.
- Second pass: repeated diacritic search plus sink/owner terms and no-diacritic Polish vocabulary (including `PIEC`, `KAMIENIE`, `SKORUPY`, `ZWORNIKI`, `SEKTOR`, `WODA`, `ETER`, `DALEJ`, `WRACAM`, `NIE`) across JS/HTML/CSS/SVG/JSON runtime material. Candidates were reconciled as inventory entries, duplicate projections of an inventoried owner, or explicit exclusions below.

### Text-based assets inspected

- SVG, HTML, CSS and JSON under runtime source/public paths. The language-specific controller SVGs are runtime-presented and inventoried. CSS `content:` declarations contain no user-facing words. Other inspected SVG text/labels are English-only, symbols, or non-localized proper names and therefore do not introduce Polish source copy.

### Explicit exclusions

- Developer comments; console/exception diagnostics not projected into UI; test fixtures/assertions; legacy and ordinary technical prose; filenames; IDs/symbols/events/Scenario point identifiers; audio without displayed text.
- Duplicate projections (for example intro modules reusing canonical Monkey PL, shared portfolio fields consumed by several modes, and repeated Guide knowledge wording) remain one owner entry with consumers noted.
- Debug preload UI is included only under `DEBUG_QA_UI`.

### Limitations and concrete risks

- Raster/binary assets were not interpreted for baked text. No runtime source assertion identified a raster asset as containing Polish baked copy, so no speculative raster item was added.
- Canvas Furnace copy remains hardcoded without locale resolution. It is split into stable logical units, with runtime values represented as templates and coherent explicit state dictionaries kept grouped.
- The canonical communication document and runtime contain different coverage sets, and independent intro EN projections use different block boundaries/wording. The audit preserves these owners and does not adjudicate wording.
